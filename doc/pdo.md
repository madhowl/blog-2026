# PHP PDO: Учебник для начинающих и среднего уровня

**Продолжительность:** 30–45 минут  
**Уровень:** Начальный / Средний  
**Цель:** Освоить базовые и продвинутые приёмы работы с базой данных через PDO в PHP: подключение, безопасные запросы, обработка ошибок и транзакции.

---

## 1. Что такое PDO и зачем он нужен

PDO (PHP Data Objects) — это слой абстракции доступа к базам данных в PHP. Он предоставляет единый интерфейс для работы с разными СУБД: MySQL, PostgreSQL, SQLite, SQL Server и другими .

**Ключевые преимущества:**
- **Переносимость:** один и тот же код работает с разными базами (меняется только DSN).
- **Безопасность:** подготовленные запросы (prepared statements) защищают от SQL-инъекций.
- **Гибкость:** объектно-ориентированный API с богатыми возможностями обработки ошибок.

Для начинающих это означает: вы учите один способ работы с базой и используете его везде, не переписывая приложение при смене СУБД.

## 2. Подключение к базе данных

### 2.1. DSN и создание объекта PDO

Подключение начинается с DSN (Data Source Name) — строки, содержащей тип драйвера, хост, имя базы и кодировку.

```php
<?php
$dsn = 'mysql:host=localhost;dbname=myapp;charset=utf8mb4';
$user = 'dbuser';
$password = 'secret';

try {
    $pdo = new PDO($dsn, $user, $password);
    // Устанавливаем режим обработки ошибок (рекомендуется)
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    die('Ошибка подключения: ' . $e->getMessage());
}
```

**Важные моменты:**
- `charset=utf8mb4` обязателен для корректной работы с кириллицей и emoji .
- Конструктор `PDO` всегда выбрасывает `PDOException` при неудачном подключении, независимо от настроек ошибок .
- Не храните учётные данные прямо в коде в production — используйте переменные окружения или конфигурационные файлы .

### 2.2. Проверка доступных драйверов

Если не уверены, какие базы поддерживаются на сервере:

```php
print_r(PDO::getAvailableDrivers());
```

## 3. Выполнение простых запросов

### 3.1. Метод `query()` для SELECT

Для запросов без пользовательского ввода можно использовать `query()`. Он возвращает объект `PDOStatement`, из которого извлекаются данные.

```php
$stmt = $pdo->query('SELECT id, name, email FROM users');

while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
    echo $row['name'] . ' — ' . $row['email'] . '<br>';
}
```

**Режимы извлечения (`fetch mode`):**
- `PDO::FETCH_ASSOC` — ассоциативный массив (рекомендуется).
- `PDO::FETCH_OBJ` — объект со свойствами.
- `PDO::FETCH_COLUMN` — одно значение из строки.

Для получения всех строк сразу используйте `fetchAll()`.

### 3.2. Метод `exec()` для INSERT, UPDATE, DELETE

`exec()` выполняет запрос и возвращает количество затронутых строк. **Не используйте его для SELECT** и **не передавайте в него пользовательские данные без подготовки** — только для простых операций с доверенными значениями.

```php
$count = $pdo->exec("UPDATE users SET active = 0 WHERE last_login < '2024-01-01'");
echo "Деактивировано пользователей: $count";
```

## 4. Подготовленные запросы (Prepared Statements) — основа безопасности

**Главное правило:** любые данные, приходящие от пользователя (формы, URL, cookie), должны передаваться в базу **только через подготовленные запросы**. Это единственная надёжная защита от SQL-инъекций .

### 4.1. Именованные плейсхолдеры (`:name`)

```php
$sql = 'SELECT * FROM users WHERE email = :email AND status = :status';
$stmt = $pdo->prepare($sql);
$stmt->execute([
    ':email' => $email,
    ':status' => 'active'
]);

$user = $stmt->fetch(PDO::FETCH_ASSOC);
```

### 4.2. Позиционные плейсхолдеры (`?`)

```php
$sql = 'INSERT INTO users (name, email) VALUES (?, ?)';
$stmt = $pdo->prepare($sql);
$stmt->execute([$name, $email]);
```

**Важно:** нельзя смешивать `?` и `:name` в одном запросе . Также один именованный плейсхолдер нельзя использовать дважды в одном запросе (если эмуляция подготовленных запросов включена) .

### 4.3. `bindValue()` vs `bindParam()`

Оба метода привязывают значения к плейсхолдерам, но есть разница:
- `bindValue()` копирует значение **сразу**.
- `bindParam()` привязывает **по ссылке** — значение берётся в момент `execute()`.

Для большинства случаев достаточно передавать массив в `execute()`. `bindParam()` полезен, когда значение переменной меняется в цикле.

```php
$stmt = $pdo->prepare('INSERT INTO logs (message, level) VALUES (:msg, :level)');

$stmt->bindParam(':msg', $message);
$stmt->bindValue(':level', 'info');

foreach ($logMessages as $message) {
    $stmt->execute(); // bindParam подставит текущее значение $message
}
```

## 5. Обработка ошибок

PDO поддерживает три режима обработки ошибок :

| Режим | Поведение | Рекомендация |
|-------|-----------|--------------|
| `ERRMODE_SILENT` | Молча устанавливает код ошибки | Устаревший, не рекомендуется |
| `ERRMODE_WARNING` | Выводит E_WARNING, скрипт продолжает работу | Для отладки |
| `ERRMODE_EXCEPTION` | Выбрасывает `PDOException` | **Рекомендуется** (по умолчанию с PHP 8.0) |

**Правильный шаблон с try-catch:**

```php
try {
    $pdo->beginTransaction();
    
    $stmt = $pdo->prepare('UPDATE accounts SET balance = balance - :amt WHERE id = :id');
    $stmt->execute([':amt' => $amount, ':id' => $fromId]);
    
    $stmt = $pdo->prepare('UPDATE accounts SET balance = balance + :amt WHERE id = :id');
    $stmt->execute([':amt' => $amount, ':id' => $toId]);
    
    $pdo->commit();
} catch (PDOException $e) {
    $pdo->rollBack();
    // Логируем ошибку, не показываем пользователю детали
    error_log('Ошибка транзакции: ' . $e->getMessage());
    echo 'Произошла ошибка. Попробуйте позже.';
}
```

**Совет:** не выводите `$e->getMessage()` напрямую пользователю в production — это может раскрыть структуру базы данных.

## 6. Транзакции

Транзакция гарантирует, что группа операций выполнится **атомарно**: либо все изменения сохранятся, либо ни одно. Это критично для финансовых операций, заказов, любых связанных данных .

### 6.1. Базовый паттерн

```php
try {
    $pdo->beginTransaction();
    
    // Операция 1
    $pdo->exec("UPDATE products SET stock = stock - 1 WHERE id = 5");
    
    // Операция 2
    $pdo->exec("INSERT INTO orders (product_id, user_id) VALUES (5, 100)");
    
    $pdo->commit();
} catch (Exception $e) {
    $pdo->rollBack();
    throw $e;
}
```

### 6.2. Проверка состояния транзакции

Метод `inTransaction()` возвращает `true`, если транзакция активна. Это полезно в блоках `catch`, чтобы избежать ошибки при повторном откате.

```php
} catch (Throwable $e) {
    if ($pdo->inTransaction()) {
        $pdo->rollBack();
    }
    throw $e;
}
```

### 6.3. Важное предупреждение

Если скрипт завершается из-за исключения **без явного вызова `rollBack()`**, PDO автоматически откатывает транзакцию при уничтожении соединения. Однако **явный `rollBack()` в `catch` — это правильная практика**, которая делает намерения программиста очевидными и предотвращает неожиданное поведение .

## 7. Краткий справочник по методам

| Метод | Назначение | Безопасность |
|-------|-----------|--------------|
| `query($sql)` | Выполнить SELECT без параметров | Только для доверенного SQL |
| `exec($sql)` | Выполнить INSERT/UPDATE/DELETE без параметров | Только для доверенного SQL |
| `prepare($sql)` | Подготовить запрос с плейсхолдерами | **Безопасно с execute()** |
| `execute([$params])` | Выполнить подготовленный запрос | ✅ |
| `fetch($mode)` | Извлечь одну строку | — |
| `fetchAll($mode)` | Извлечь все строки | — |
| `rowCount()` | Количество затронутых строк | — |
| `lastInsertId()` | ID последней вставленной записи | — |
| `beginTransaction()` | Начать транзакцию | — |
| `commit()` | Зафиксировать изменения | — |
| `rollBack()` | Отменить изменения | — |

## 8. Упражнения для закрепления (10–15 минут)

1. **Подключение:** создайте файл `db.php`, который возвращает объект `$pdo` с настройками `ERRMODE_EXCEPTION` и `FETCH_ASSOC` по умолчанию.

2. **Безопасный SELECT:** напишите запрос, который выбирает пользователя по email, используя именованный плейсхолдер. Передайте email из переменной.

3. **Вставка с транзакцией:** создайте две таблицы (`orders` и `order_items`). Напишите скрипт, который вставляет заказ и две позиции в одной транзакции. Если вторая вставка завершится ошибкой (например, из-за несуществующего внешнего ключа), проверьте, что заказ тоже не сохранился.

4. **Исследование:** выполните `print_r(PDO::getAvailableDrivers())` на своём сервере. Какие драйверы доступны?

## 9. Что дальше

После освоения материала вы готовы к:
- Построению слоя репозиториев (инкапсуляция запросов в классы).
- Работе с JOIN-запросами через PDO.
- Использованию `PDO::ATTR_EMULATE_PREPARES = false` для настоящих серверных подготовленных запросов (если драйвер поддерживает).
- Миграции с MySQL на PostgreSQL или SQLite путём изменения только DSN.

PDO — это не просто способ подключиться к базе. Это фундамент безопасной и переносимой работы с данными в PHP. Освоив подготовленные запросы и транзакции, вы избежите большинства типичных ошибок начинающих разработчиков.
